# TRUCKLY — ML Extension: Learning to Prune the Candidate Set

## Deliverable 23 — circularity audit (what was NOT built, and why)

| Candidate ML task | Verdict | Reason |
|---|---|---|
| Fuel-consumption prediction | **REJECTED** | fuel is generated by a known formula; a model would recover our own constant. R2 would measure nothing. |
| Travel-time prediction | **REJECTED** | durations come from a deterministic distance/speed model. Same circularity. |
| Feasibility prediction | **REJECTED** | exactly recoverable from the hard constraints; a classifier is a lossy re-implementation of the filter. |
| **Candidate pruning (`selected_by_optimiser`)** | **BUILT** | the label comes from a global combinatorial optimisation over competing trucks and is not a function of any single candidate's features. |

> **Truckly does not work because of machine learning.** The optimiser is the decision-maker; the classifier only shrinks the search space it works over. Removing the ML layer changes runtime, not the result.

## Data and split

- 24,764 candidate rows, positive rate **24.0%**
- Split **by instance, never by row** (60 train / 20 validation / 20 test instances). Candidates in the same simulated day compete for the same shipments; a row-wise split would leak.
- Accuracy is **not** reported: under this class imbalance a trivial all-negative classifier scores 76.0%.
